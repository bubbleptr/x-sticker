# 第二阶段：浏览器创建平台草稿

更新日期：2026-09-24。当前实现支持小红书图文笔记、抖音图文作品，使用现有 Chrome 登录状态。微信暂缓，等用户提供 Relay 后再适配图片消息草稿。

## 使用方式

1. 执行 `npm ci`、`npm run build`，在 Chrome 扩展管理页加载或重新加载 `dist/`，然后刷新已经打开的 X 和创作者中心页面。旧标签页不会自动载入新脚本，未刷新时分享菜单可能没有「做成卡贴」，旧版任务面板也可能仍留在后台页面。本版使用两个创作者中心的站点权限、本地存储权限和工具栏的声明式站点规则。
2. 在 X 文字帖分享菜单选择「做成卡贴」，或点击工具栏图标打开同一个页内预览。插件入口仅在 HTTPS 的 x.com / twitter.com 可用，其他网站不打开界面。
3. 左侧查看大图，右侧 Inspector 调整图片、选择小红书和抖音、编辑标题和正文。预览默认「适应窗口」，切到「100%」可滚动检查原始 PNG 的文字细节。标题最多 20 个字，正文最多 1000 个字；超长内容要求手动修改，不自动截断。
4. 点击「同步到草稿」，界面立即切换到独立的同步状态页。扩展固定本次 PNG 与文案，分别打开任务标签页，上传、填写、暂存，再重新打开核对；任务进度不占用预览区域。
5. 状态页显示各平台的实际步骤和结果，可打开原标签页或「返回预览」继续编辑；返回会保留文案，不会重复提交任务。顶部「同步记录」可重新查看历史任务，并停止自动操作。遇到登录、验证码或页面变化时，按提示打开后台接手；处理后回到 X 同步页点击「检查并继续」。抖音存在旧稿时，X 会明确显示「抖音有旧草稿未发布」，并提供「查看抖音旧草稿」和「重新同步到抖音」。小红书和抖音页面不显示插件悬浮面板。
6. 草稿核对成功后，由用户自行发布。扩展没有发布操作，也不以私密发布、定时发布替代草稿。

关闭预览不影响已经创建的任务。X 同步页的「停止自动操作」可中止后续步骤；手动编辑创作者中心内容也会暂停自动操作。关闭任务标签页或重启浏览器后，不重新上传，不自动创建替代标签页；本地保留图片和任务记录，用户自行到平台检查。

第一版每个平台每次上传一张 PNG，沿用现有 3:4 / 9:16 贴图选项。平台当前推荐比例见下文，优先使用 3:4。

抖音的「重新同步到抖音」复用本次任务、贴图和文案。它只用于明确尚未上传的旧稿冲突：处理旧稿后点击可继续；旧稿仍在时再次提示，不自动放弃或覆盖，也不产生第二个任务。已经开始上传或保存的任务仍沿检查点核对，不重新上传。任务标签页已关闭时仍需要人工核对，不自动打开替代页。

## 平台保存语义

| 平台 | 保存与恢复 | 限制 |
| --- | --- | --- |
| 小红书 | 图文编辑器「暂存离开」，从草稿箱按标题找到唯一草稿，点击「编辑」重新核对 | 平台明确草稿存在当前浏览器本地。清理浏览器数据会删除，不承诺手机端或其他电脑可见。遇到同名草稿时停止，避免打开错误内容。 |
| 抖音 | 图文编辑器「暂存离开」，回到上传页后点击「继续编辑」重新核对 | 页面保留「上次未发布的图文」。新任务发现这个提示会停止，避免覆盖。已经验证同一会话恢复；不承诺云端、跨设备或长期保存。 |

当前账号上传页显示：小红书单图最大 32 MB，推荐 PNG/JPG/JPEG/WebP、比例 3:4 至 2:1、至少 720×960；抖音单图不超过 50 MB、最多 35 张，推荐 JPG/JPEG/PNG/WebP、3:4 或 4:3。两者均不支持 GIF。这是当日页面观察，扩展第一版输入另限制为一张不超过 10 MB 的 PNG。

## 实现边界

- 继续使用 TypeScript、Vite、CRXJS 和 Chrome MV3；无需服务端或独立浏览器进程。
- 开页使用扩展的 `chrome.tabs.create/update`，页面操作使用 content script 和 `chrome.runtime` 消息；没有 CDP、`chrome.debugger` 或浏览器远程调试端口。工具栏通过 Chrome 声明式站点规则仅在 X/Twitter 启用，无独立 popup。
- 小红书与抖音各自的 content script 只处理后台为该任务创建并绑定的标签页，普通创作者中心标签页不执行任务。
- 创作者中心执行器不添加界面；停止和继续指令从 X 的状态页经后台转发到原任务标签页，其他网站不能发起这些操作。
- PNG Blob 保存在扩展 IndexedDB，任务与检查点保存在 `chrome.storage.local`。后台休眠后仍能读取，账号 Cookie 和登录令牌不导出。
- 上传使用页面文件输入框与 `File` / `DataTransfer`；标题和小红书正文使用浏览器原生编辑命令，不调用平台私有接口。抖音正文通过编辑器的纯文本粘贴事件写入，保留原有段落与叶节点，且必须等到平台正文计数与预期 UTF-16 长度一致。小红书还须等到笔记预览显示相同标题，才允许保存。
- 小红书保存控件位于关闭的 Shadow DOM，通过 Chrome 的 `chrome.dom.openOrClosedShadowRoot` 读取。仅允许精确匹配「保存草稿」「存草稿」「暂存离开」的保存控件；重复、禁用或陌生按钮都会停止。
- 成功需要重新打开草稿，核对标题、正文、单张图片和账号，并验证保存前后的解码图片像素摘要相同。图片无法读取或摘要改变时交给人工，不以数量相同代替图片一致。
- 保存前记录检查点。保存结果不明时恢复只检查和重开，不重复点击保存；上传中断后不重新上传。不同平台各自记录结果，同一平台不同时执行多个任务。
- 素材保留在扩展本地，目前没有历史任务清理界面。清除扩展数据或卸载会清除扩展保存的本地记录。

## 验证记录与剩余验证

2026-09-24 使用一张 1080×1440 的测试 PNG、短标题和两行正文，在当前已登录账号进行了真实页面操作：

| 平台 | 页面操作结果 |
| --- | --- |
| 小红书 | 上传成功，填写标题和正文，点击「暂存离开」出现「保存成功」，草稿箱出现测试图文，重新打开后标题、两行正文和单张图片一致。 |
| 抖音 | 上传成功，填写标题和正文，点击「暂存离开」返回上传页并出现未发布图文提示；「继续编辑」恢复标题、两行正文和单张图片。 |

测试草稿标题为「X Sticker草稿测试」，全程没有点击发布，也未编辑原有内容。真实页面验证通过浏览器工具操作，证明保存入口和恢复行为；它不能代替本版扩展在真实平台上的全链路验收。

自动化回归覆盖任务持久化、消息来源、上传和保存恢复、账号变化、用户停止、发布按钮拒绝、旧图片拒绝，以及预览更新时禁止提交旧素材。本地真实 Chrome 集成测试验证 `FileList`、富文本输入、关闭的 Shadow DOM 和保存重开图片比较；测试页面不冒充平台成功。

真实加载 v0.2.0 后，小红书的扩展上传、正文填写和暂存均已执行，但重开时标题为空，任务正确停留在「需要接手」。输入框的即时值不能证明平台已提交标题；正常浏览器输入后，平台预览也会稍后才同步。

v0.2.1 改为原生标题编辑事务，并等待小红书笔记预览确认标题后再保存。回归测试保存独立的页面编辑状态，覆盖异步标题同步；不再直接读取输入框值充当平台保存结果。修复版仍需用户重新加载扩展、刷新 X 后在真实平台复测；抖音的新版扩展全链路同样尚未验收。

运行验证：

```bash
CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm test
npm run build
```

v0.2.2 将编辑和同步进度拆成两个视图。预览画布保留导出图片的原始分辨率，仅用 CSS 适配视口；「100%」显示真实像素。组件回归覆盖提交后切页、返回保留文案、后台状态更新、失败不误报成功和旧请求不覆盖新任务。

v0.2.3 移除工具栏独立弹窗与创作者中心任务面板，统一从 X 页内预览查看和控制任务。回归覆盖外站点击不打开界面、创作者中心不增加 DOM、停止/继续消息的来源与任务绑定，以及控制指令不会阻塞后台状态回报。

v0.2.4 为抖音旧稿冲突增加结构化状态和 X 内的「重新同步到抖音」按钮。回归覆盖旧稿未处理时持续提示、处理后同一任务仅上传一次、上传检查点写入期间出现旧稿，以及旧状态清除。Vite 截图验证提示、重试和后续正常进度；使用本地模拟状态，不代表真实平台已验证此版本。

v0.2.4 真实抖音任务曾出现标题、图片已保存，正文重开后为 0/1000；X 正确停在核对超时，没有误报成功。旧实现只比较正文 DOM 文本，不能证明编辑器的保存模型接受了输入。通过原生粘贴补回原文后，平台计数为 152/1000，暂存重开后正文完整；这验证了平台的粘贴和保存路径。现场也确认一个双码元 emoji 使计数增加 2，计数包含换行。

v0.2.5 调整抖音正文输入方式，并在保存前及重开后检查平台计数；未识别计数或计数不一致均暂停。核对超时明确指出缺失的是正文、标题、图片或对应平台确认信号。本地 Chrome 契约测试先复现「DOM 正文完整、独立保存模型为空」仍点击暂存的问题，再验证模型异步接受后才保存、拒绝接受时不保存。测试 fixture 不等同于抖音 editor-kit；新版扩展发出的合成粘贴事件是否被真实平台接受，仍需重载扩展后复测。当前用户草稿已通过浏览器补全并暂存，未发布。

本地 Vite 预览已用真实 Chrome 截图检查桌面浮层、扩展弹窗、窄屏和独立状态页，并验证 Inspector 独立滚动、缩放与返回预览不重复创建任务。状态截图使用本地模拟任务，不代表平台上传已完成。截图和一次性验证脚本位于被忽略的 `artifacts/`，不提交账号数据或带签名的图片地址。

## 微信延期范围

微信不申请权限、不实现浏览器适配器，也不作为本版验收条件。未来通过用户提供的 Relay 适配以贴图为主的图片消息草稿；协议和鉴权依据 Relay 实际能力确定，仍由人最终发布。

此前核对的[微信新增草稿官方文档](https://developers.weixin.qq.com/doc/service/api/draftbox/draftmanage/api_draft_add.html)区分文章 `news` 与图片消息 `newspic`；这不证明用户 Relay 支持相同协议。图片素材上传、文章内插图与图片消息草稿是不同结果，未来目标是最后一种。
