# 第二阶段：浏览器创建平台草稿

更新日期：2026-09-24。当前实现支持小红书图文笔记、抖音图文作品，使用现有 Chrome 登录状态。微信暂缓，等用户提供 Relay 后再适配图片消息草稿。

## 使用方式

1. 执行 `npm ci`、`npm run build`，在 Chrome 扩展管理页加载或重新加载 `dist/`，然后刷新已经打开的 X 页面。旧标签页不会自动载入新脚本，未刷新时分享菜单可能没有「做成卡贴」。本版增加两个创作者中心的站点权限和本地存储权限。
2. 在 X 文字帖分享菜单选择「做成卡贴」，也可打开扩展工具栏弹窗。
3. 调整图片，选择小红书、抖音，检查并编辑标题和正文。标题最多 20 个字，正文最多 1000 个字；超长内容要求手动修改，不自动截断。
4. 点击「存到草稿」。扩展固定本次 PNG 与文案，分别打开任务标签页，上传、填写、暂存，再重新打开核对。
5. 在「草稿任务」查看状态并打开原标签页。遇到登录、验证码、已有内容或页面变化时，按提示接手；处理后可在页面任务面板点击「检查并继续」。
6. 草稿核对成功后，由用户自行发布。扩展没有发布操作，也不以私密发布、定时发布替代草稿。

关闭预览不影响已经创建的任务。页面上的「停止自动操作」可中止后续步骤；手动编辑页面内容也会暂停自动操作。关闭任务标签页或重启浏览器后，不重新上传，不自动创建替代标签页；本地保留图片和任务记录，用户自行到平台检查。

第一版每个平台每次上传一张 PNG，沿用现有 3:4 / 9:16 贴图选项。平台当前推荐比例见下文，优先使用 3:4。

## 平台保存语义

| 平台 | 保存与恢复 | 限制 |
| --- | --- | --- |
| 小红书 | 图文编辑器「暂存离开」，从草稿箱按标题找到唯一草稿，点击「编辑」重新核对 | 平台明确草稿存在当前浏览器本地。清理浏览器数据会删除，不承诺手机端或其他电脑可见。遇到同名草稿时停止，避免打开错误内容。 |
| 抖音 | 图文编辑器「暂存离开」，回到上传页后点击「继续编辑」重新核对 | 页面保留「上次未发布的图文」。新任务发现这个提示会停止，避免覆盖。已经验证同一会话恢复；不承诺云端、跨设备或长期保存。 |

当前账号上传页显示：小红书单图最大 32 MB，推荐 PNG/JPG/JPEG/WebP、比例 3:4 至 2:1、至少 720×960；抖音单图不超过 50 MB、最多 35 张，推荐 JPG/JPEG/PNG/WebP、3:4 或 4:3。两者均不支持 GIF。这是当日页面观察，扩展第一版输入另限制为一张不超过 10 MB 的 PNG。

## 实现边界

- 继续使用 TypeScript、Vite、CRXJS 和 Chrome MV3；无需服务端或独立浏览器进程。
- 小红书与抖音各自的 content script 只处理后台为该任务创建并绑定的标签页，普通创作者中心标签页不执行任务。
- PNG Blob 保存在扩展 IndexedDB，任务与检查点保存在 `chrome.storage.local`。后台休眠后仍能读取，账号 Cookie 和登录令牌不导出。
- 上传使用页面文件输入框与 `File` / `DataTransfer`；标题和正文使用浏览器原生编辑命令，不调用平台私有接口。小红书还须等到笔记预览显示相同标题，才允许保存。
- 小红书保存控件位于关闭的 Shadow DOM，通过 Chrome 的 `chrome.dom.openOrClosedShadowRoot` 读取。仅允许精确匹配「保存草稿」「存草稿」「暂存离开」的保存控件；重复、禁用或陌生按钮都会停止。
- 成功需要重新打开草稿，核对标题、正文、单张图片和账号，并验证保存前后的解码图片像素摘要相同。图片无法读取或摘要改变时交给人工，不以数量相同代替图片一致。
- 保存前记录检查点。保存结果不明时恢复只检查和重开，不重复点击保存；上传中断后不重新上传。不同平台各自记录结果，同一平台不同时执行多个任务。
- 素材保留在扩展本地，目前没有历史任务清理界面。清除扩展数据或卸载会清除扩展保存的本地记录。

## 验证记录与剩余验证

2026-09-24 使用一张 1080×1440 的测试 PNG、短标题和两行正文，在当前已登录账号进行了真实页面操作：

| 平台 | 页面操作结果 |
| --- | --- |
| 小红书 | 上传成功，填写标题和正文，点击「暂存离开」出现「保存成功」，草稿箱出现测试图文，重新打开后标题、两行正文和单张图片一致。 |
| 抖音 | 上传成功，填写标题和正文，点击「暂存离开」返回上传页并出现未发布图文提示；「继续编辑」恢复标题、两行正文和单张图片。 |

测试草稿标题为「X Sticker草稿测试」，全程没有点击发布，也未编辑原有内容。真实页面验证通过浏览器工具操作，证明保存入口和恢复行为；它不能代替本版扩展在真实平台上的全链路验收。

自动化回归覆盖任务持久化、消息来源、上传和保存恢复、账号变化、用户停止、发布按钮拒绝、旧图片拒绝，以及预览更新时禁止提交旧素材。本地真实 Chrome 集成测试验证 `FileList`、富文本输入、关闭的 Shadow DOM 和保存重开图片比较；测试页面不冒充平台成功。

真实加载 v0.2.0 后，小红书的扩展上传、正文填写和暂存均已执行，但重开时标题为空，任务正确停留在「需要接手」。输入框的即时值不能证明平台已提交标题；正常浏览器输入后，平台预览也会稍后才同步。

v0.2.1 改为原生标题编辑事务，并等待小红书笔记预览确认标题后再保存。回归测试保存独立的页面编辑状态，覆盖异步标题同步；不再直接读取输入框值充当平台保存结果。修复版仍需用户重新加载扩展、刷新 X 后在真实平台复测；抖音的新版扩展全链路同样尚未验收。

运行验证：

```bash
CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm test
npm run build
```

本地 Vite 预览已用浏览器截图检查弹窗和页内浮层，并检查窄屏滚动。截图和一次性验证脚本位于被忽略的 `artifacts/`，不提交账号数据或带签名的图片地址。

## 微信延期范围

微信不申请权限、不实现浏览器适配器，也不作为本版验收条件。未来通过用户提供的 Relay 适配以贴图为主的图片消息草稿；协议和鉴权依据 Relay 实际能力确定，仍由人最终发布。

此前核对的[微信新增草稿官方文档](https://developers.weixin.qq.com/doc/service/api/draftbox/draftmanage/api_draft_add.html)区分文章 `news` 与图片消息 `newspic`；这不证明用户 Relay 支持相同协议。图片素材上传、文章内插图与图片消息草稿是不同结果，未来目标是最后一种。
